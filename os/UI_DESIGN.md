# 面板 UI 设计说明

## 目标

面板以小米智能家居产品的克制深色视觉为参考：深灰底色、圆角信息卡、蓝色选中/开启态、低对比度辅助信息。界面围绕“扫一眼状态、直接按控制、快速改每路用途”设计。品牌和图标使用通用表达，不复制小米专有标识或素材。

## 页面结构

1. **首页**：顶栏 Matter 连接状态与实时钟；可自定义的“名称的家”标题（默认“栖居的家”）；日期/问候；天气温度、天气描述、湿度和地点；全屋灯具开启数量；三张实体通道卡片；未来数小时逐小时天气；最多三个固定快捷场景。
2. **设置**：原首页/房间/更多 UI 导航统一移入设置的分页；提供面板名称、天气数据源、地点、天气联动背景、昼夜联动、房间灯具状态及主题等设置。真实设备通过天气服务适配器获取天气，当前原型用选择器模拟天气状态。
3. **主题库**：清透蓝、暖阳、薄荷、浅色四套主题；主题只改变配色和氛围，控制状态卡保持一致的可读性。浅色模式使用深色字体和深色强调图标/标记。后续可拓展用户上传背景与字体大小。
4. **快捷场景第二层**：点击首页快捷场景“更多”打开居中毛玻璃场景库，遮罩约 50% 透明度并模糊背景，展示 5 个测试场景：回家、休息、离家、观影、阅读。点击会改变示例灯具状态；长按打开“固定首页”开关，最多固定 3 个。原型内置场景为交互示例，真实手机场景需由家庭控制器同步。
5. **通道设置**：每路可设置显示名称、用途（灯具控制/自定义开关）、输入 GPIO 与输出驱动 GPIO 的只读硬件信息。保存前提示 Matter 端点类型变化可能要求重新配置设备。
6. **自定义开关详情**：显示动作/联动状态与“触发测试”入口。动作目标由本地设置定义；自定义开关在 Matter 中采用 Generic Switch device type，不计入灯具总数。
7. **系统状态**：Wi-Fi/Matter commissioning 状态、固件版本、开关输入状态、继电器输出状态、重启与恢复出厂设置入口。恢复出厂需要二次确认。

## 视觉参数

- 背景：`#101114`；卡片：`#1B1D22`；辅助层：`#24272E`。
- 主文字：`#F3F4F6`；次文字：`#979BA5`；开启强调：`#5D9DFF`；在线状态：`#6AD9B3`。
- 卡片圆角 22–24 px，点击区最小 44×44 px，状态不只用颜色表达，同时显示“已开启/已关闭”。
- 目标分辨率 800×480，UI 画布按 5:3 原生比例布局。实际 4.3inch DSI LCD 与 ESP32-S3 的接口不兼容，需桥接或更换 display host 才可上板显示。

## 事件与数据流

天气 API -> 网络天气服务适配器（HTTPS、周期刷新、缓存、错误/离线回退）-> 天气状态模型 -> 首页天气与动态背景；设备系统时钟/时区 -> 时段状态 -> 问候与昼夜主题。Matter Fabric 可提供 Matter 温湿度传感器读数，但天气预报和城市天气并不是 Matter 的天气服务。Matter 可暴露标准温度/相对湿度测量集群来发布本机传感器读数；它不取代互联网天气数据源。

所有发现/订阅的灯具状态 -> 全屋灯具状态集合 -> 首页“已开数量/灯具总数”。集合只收纳 On/Off Light 类型设备；Generic Switch 按键事件不能作为灯具状态，因此自定义开关不加入分子或分母。真实全屋统计需要家庭控制器将其他 Matter 灯具状态同步给面板；当前 ESP-Matter 应用自身不是全屋控制器。

实体开关 GPIO -> 消抖输入任务 -> 通道用途路由 -> (灯具) Matter On/Off attribute + 隔离输出；(自定义) Matter Generic Switch event + 本地自定义动作。Matter 客户端对灯具 On/Off 的写入走相同的输出驱动层。UI 仅订阅应用状态模型并调用设置服务，不直接操作 GPIO 或 Matter 属性。

## 当前交付状态

`ui/panel-preview.html` 和 `ui/settings.html` 是可点击的 800×480（5:3）HTML 原型，包含灯具数量汇总、第三路自定义开关、日期时间、天气切换、四款主题、逐小时预报、可编辑面板名称、设置分页、服务 API 地址、NVS 测试模式固件接口、居中毛玻璃场景库和长按固定场景交互。浅色主题显式设置深色文字/图标强调色。全屋灯具列表有示例远端灯具，控制其开关会实时更新灯具统计；自定义开关不计入灯具数。五个快捷场景可点选并改变演示灯具状态；固定场景保存在浏览器本地且上限为 3。演示天气与房间设备状态不是 Matter Fabric 实时数据。当前固件已定义 service provider C API 和安全测试模式，但 HTTP routes、真实 provider、真正显示驱动尚未实现；具体 4.3inch DSI 屏也不能直接接 ESP32-S3。

## 完成设备 UI 所需的硬件参数

- 具体 ESP32-S3 DevKitC 板卡版本/模组型号及其原理图
- LCD 型号、分辨率、接口（SPI/RGB/MIPI 等）、背光控制 GPIO
- 触控芯片与 I2C/SPI 地址和中断/复位 GPIO
- 实体开关是瞬时按钮还是保持型翘板
- 每路自定义模式的目标动作（例如 Matter Generic Switch 场景触发，或本机联动）
- 继电器模块输入极性、隔离方式、上电默认状态
